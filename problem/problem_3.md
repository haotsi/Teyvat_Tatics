- 战斗开始后（即上述问题1）

**在游戏中需要进一步实现的功能：**

1、新增命之座合成时的装备管理机制，并对原设定作一定修改： 
当在合成面板中点击“合成”按钮时，必须按以下顺序处理：
- 卸下双方装备
    - 获取参与合成的两个角色（称为 pieceA 和 pieceB）。
    - 对于每个角色：
        - 若拥有武器，调用 unequipWeapon(piece) 将武器移入武器背包。
        - 遍历所有 5 个圣遗物槽位，若该槽位有圣遗物，调用 unequipArtifact(piece, slot) 移入圣遗物背包。
    - 注意：unequipWeapon 和 unequipArtifact 在现有实现中会将卸下的装备追加到背包末尾，且不检查容量。这是预期行为，但需配合后续溢出处理。
- 删除原角色
    - 从储存栏或棋盘（两者之一）中移除 pieceA 和 pieceB 并 delete。
    - 若角色在棋盘上，需先将其从 Board 中移除（removePiece）。
- 创建新角色
    - 生成一个同名同基础属性的新角色，命之座等级 = pieceA.constellation + pieceB.constellation + 1，上限 6。
    - 新角色初始不携带任何武器和圣遗物（装备栏全空）。
    - 新角色默认加入储存栏（addToStorage）。
- 背包溢出自动出售
    - 定义背包容量上限：武器背包 QVector<Weapon> 最多 20 件，圣遗物背包 QVector<Artifact> 最多 20 件。
    - 在每次向背包添加物品时（包括购买、卸下装备、合成卸装、战斗奖励等）检查容量。
    - 若添加后超出容量，立即自动出售超出的物品：
        - 出售规则：按物品的 出售价格（sellPrice()） 从低到高出售，直到不超过容量为止。
        - 若价格相同，出售较早加入背包的物品（即按 QVector 下标从小到大）。
        - 出售所得摩拉直接加到玩家 m_mora 中。
        - 出售行为应记录一条日志（emit messageLogged("已自动出售 ... 获得 X 摩拉")）。
    - 注意：现有代码中武器和圣遗物背包均无容量限制，需新增容量检查函数，并在所有 append 操作后调用 enforceBackpackCapacity()。
- 与原有 mergeCharactersDirect 的冲突解决：原有逻辑中合成时会保留较高星级的武器和圣遗物，本需求要求全部卸下且新角色无装备。因此必须完全替换 mergeCharactersDirect 的实现，废弃旧逻辑
